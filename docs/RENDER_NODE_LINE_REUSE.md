# Reuse the renderer's exact private node line

The installer renderer previously serialized the same private immutable node
manifest twice: once to compute the ingress/readiness node SHA, then again for
the returned `launch.json` artifact. It now retains the first exact JSON+LF line
for **both** uses. This removes one redundant producer marshal, not validation.

The original readiness `DaemonUnit` and ingress `Unit` generators still run in
the same order, including every original decoder, semantic/composition check,
byte ceiling, unit transformation and error return. The returned five paths and
their bytes are unchanged. The old ingress wrapper remains unchanged for every
other caller. Three private production callers now use the shared literal
constructor: the original wrapper, Plan validation, and the renderer; each
computes its own SHA from that call's exact node JSON+LF bytes. No callback, IO,
caller mutation or external input buffer intervenes. Each renderer call owns a
fresh mutable output line. No validation/digest/data cache, shared pool, decoded
input bypass, independent unit template or consumer permission is introduced.

This private generator is **not full Plan validation**: for example an empty
release digest can leave its generated composition unchanged, even though the
existing Plan validator rejects that Plan. Reusing generated bytes must not
become a reason to bypass that caller policy. Likewise the existing composition
validator does not bind the node-launch SHA to the node manifest. Only the
private producer computes that digest here; no public digest selector is added.

The file hash's completed SHA is also converted to lowercase hex with
`encoding/hex`, instead of generic `fmt` formatting. The original `io.Copy`+
`fmt` hash oracle and all 178 hash-scratch cases remain unchanged. Seek, context,
size+1 limiter, errors, file reads, final count/SHA and the verifier's `Sync`
remain unchanged; there is no additional scratch/pool/cached hash.

Three new common Go tests compare the full renderer against a pinned original
body. Its node/ingress/JSON producers are independent test literals/standard
JSON, not the candidate builders. All original production generators still run
in the oracle. There are 43 named leaf cases and two outer version groups:
8 version/metrics/device combinations; 32 bad/missing pins, device, resource,
oversize and invalid-UTF8 controls; and 3 fresh-output, changed-caller and
not-full-Plan-authority controls. Caller values, all five output byte strings,
exact errors, nil-on-error and independent per-call buffers are checked.

These are static redundant-work/formatting opportunities, **not a measured
speedup, CPU/IO profile, timeout root cause, budget-fit, SLO or native acceptance
claim**. New-source CI must qualify its actual scope separately. All old tests,
oracles, counts, race repetitions, matrix and order are retained. CI stays at
25 minutes and Go race at 20 minutes; all host resource/IO/acceptance caps remain.
No V100 load or deployment is performed. Whole CI, original Linux/KVM/long-load
acceptance and the operational compatibility/budget/handoff/release/rollback
work remain incomplete. The published preview is not requalified.
