Positive manager/image/placement/cgroup/mount/quota controls remain software
models; they do not qualify real systemd/KVM, complete reclaim, power-loss/reboot,
activation, upgrades/rollback or sustained load. No production command currently

## Closed read-only kernel quota path

The runtime FD is fixed by the installed layout and compared with state/runtime
device and directory identities before/after reads. The dedicated quota reader
duplicates its held FD safely, verifies writable ext4, configured UUID, exact
mount identity and enforced project quota, configured filesystem device, and
unassigned/non-inheriting runtime root. It admits only `Q_GETFMT` and bounded
reserved-project `Q_GETQUOTA` operations. There is **no reachable SET, SYNC,
quota-on/off, initialization, reserve/clear/release or driver constructor** in
this path. Reading does not establish durability of earlier writes.

Require v2 64-bit accounting and complete valid kernel fields. Read **every**
immutable reserved project, not only projects with owner JSON. Unknown nonzero
usage/limits/reservations and never-attempted owners with nonempty records refuse.
An attempted owner may retain only the existing immutable known quota shape;
unfinished ownership remains allocated even if its usage is zero. Recheck mount
and root project identity after reads. Errors, partial fields, range drift and
uncertain results publish no partial report. The [Linux quota API](https://www.man7.org/linux/man-pages/man2/quotactl_fd.2.html)
and [complete quota fields](https://www.man7.org/linux/man-pages/man2/q_getquota.2const.html)
define these getters; this component never changes the existing lifecycle quota
barriers or release ordering.
Context is checked between reads; it is not a hard deadline for a blocking
filesystem/kernel syscall. No device-I/O latency or timeout/reaping guarantee is
inferred from the software getter controls.

## Cold policy and catalog compatibility

The installed initial/runtime composition forbids snapshot bootstrap/migration.
Therefore **any catalog, even empty, is a conflict under that installed policy**;
the inspector never creates a catalog lock or enables snapshots to pass a test.

Separate pure metadata decoders reuse the original generic backend/ownership/
catalog-index/snapshot-manifest validators. They validate immutable bindings,
retained phases/budgets, pin uniqueness and missing/retired pin targets, fixed

or certify complete snapshot inventory. They are compatible-reader groundwork,
not snapshot installation/activation permission. The ordinary catalog reader
retains its original directory sync, locking and object verification behavior.
