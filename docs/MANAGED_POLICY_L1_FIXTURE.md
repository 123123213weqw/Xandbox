# Opt-in fresh managed-v2 owned-L1 fixture — actual predecessors retained

**No complete new root CLI, real kernel-positive, TLS/KVM or cold acceptance
is claimed. Two actual populated-gate predecessors failed and are retained.**
The [new proposal supersession code](PENDING_POLICY_SUPERSESSION.md) and its
changed binaries cannot inherit old installation/ingress reports. Runtime Go
source remains pinned to `9db9603`; the launcher must require a successful fresh
native qualification, compare all declared current ELF hashes, and retain its
own separately frozen harness source/inputs and raw report.

`kvm_systemd_host.py --managed-assets PRIVATE_MANIFEST --managed-case CASE` is
exclusive with all older profiles. The closed cases are `populated-gate`
(default) and `active-stop`; each needs its **own fresh disk, launch and report**.
The case is stored in private image metadata, echoed in every closed reply and
bound across the original-disk cold checkpoint. A result from one case cannot
satisfy the other case's flags. Case selection without the managed profile is
rejected before image work. It starts only from `configure_root`, not an existing deployment.
The image stages exactly 13 release roles plus installer, publisher and the
opt-in managed PKI producer. No ordinary main/ingress unit, production state or
installation is preinstalled. Old v1 builder source pins are not reused for the
new programs. Each input must be regular, bounded and SHA-pinned; program roles
also pass the existing static-ELF validation.

The existing 16 GiB / CPU12 / 24 GiB disk, no-NIC, launcher UID/netns/cgroup/lease
bounds and test operator limits are unchanged. Building is offline extraction
and metadata assembly only: no chroot, downloaded userspace/VMM execution on L0,
shared host service/module/mount/quota/sysctl/network mutation or task fallback.

The `populated-gate` CLI sees an already stopped ingress for its population
differential; that case alone cannot qualify the active-unit production-stop
branch. The separately implemented `active-stop` case does not exercise the
population negative control. Neither case has a complete accepted actual scope.
The first populated-gate attempt below is a failure, not a partial acceptance.
Both source-bound successful scopes and independent absence audits remain required.
Uncommitted supersession, its repeated-failure/cut matrix,
all remaining filesystem/media faults and current-artifact runtime/SLO matrices
also remain required. An eventual pass of this named profile must not be expanded
to any of those claims, a full production milestone or the whole goal.

The pure unit controls validate assembly exclusivity, closed messages/receipts,
trace predicates/guards, old-versus-new activation observation, timing order,
negative-control ownership, case isolation/cold binding and failure reporting.
They do not execute the above
actual checks. Only actual source-bound reports and independent resource audits

## Preserved first actual failure

The [first populated-gate original](validation/managed-policy-l1-populated-failed-v1.json)
used frozen harness `848b814`, all 23 qualified current native artifacts and 249
Linux pure tests/zero skips. It reached one actual L1 boot but failed during the
checkpoint's TLS continuity check. The script wrongly attempted a successful
request on the same transport **after** its old-token 401. The production
`gatewayError` explicitly sets `Connection: close`; Python correctly reconnected,
and the strict transport identity check rejected that reconnect. This is not an
accepted case or a claim that the production gateway needs keepalive on errors.

The correction preserves old-key refusal on the established transport, requires
its intended 401 close, and checks new-key success separately. It changes only
fixture code/control tests, not Go artifacts, runtime limits or deadlines. The
failed original's report/console remain private and hash-bound; independent
read-only audit found its one declared outer generation and all owned paths
absent without supplemental cleanup. A corrected fresh run is still required.

The [second actual original](validation/managed-policy-l1-populated-failed-v2.json)
used frozen `a966af9` and 250 Linux pure tests/zero skips. It passed the corrected
TLS sequence but failed later in the warm-drain callback: the test had explicitly
stopped main, then incorrectly expected policy reconciliation to start main.
The production policy manager intentionally refuses an inactive main. This is
another fixture-contract error, not a reason to add implicit main start to policy
maintenance. Code review had identified that callback while the frozen original
was still running; its eventual failure matched that location.

The corrected callback proves main is already stopped, performs a separate
fixed owned root `systemctl start` for this intentional warm restart, then checks
TLS and exact policy reconciliation. No maintenance continuity check is removed,
no resume is implicit, and no production Go byte or deadline changes. The second
original and independent one-generation absence audit are retained separately;
it is not accepted or merged with the first attempt into a pass.
